# KnowWork 界面规范

| 项 | 内容 |
|---|---|
| 状态 | 已定（2026-10-18），组件库从 Ant Design 换成 ChatGPT 官方设计系统（2026-10-20，已全部换完） |
| 风格 | 使用端和管理后台都照 ChatGPT：单色、克制，彩色只表达状态和链接 |
| 技术栈 | React 19、TypeScript、Vite、Tailwind 4、`@openai/apps-sdk-ui`（OpenAI 发布的 ChatGPT 设计系统，MIT）、Radix |
| 组件 | 先用 `@openai/apps-sdk-ui/components/*`，它没有的在 `web/src/ui/` 里用 Radix 自建 |

交付任何界面前逐条对照本文自查。没写到的情况，先看组件库里有没有对应组件和令牌，照它来；再看 ChatGPT 本身怎么做（设置页、企业管理台、对话页），不自创。

## 1. 令牌

颜色、字号、圆角、阴影都用组件库的令牌，不写字面量：

- CSS 里用变量：`--color-text`、`--color-text-secondary`、`--color-text-tertiary`、`--color-surface`、`--color-surface-secondary`、`--color-border`、`--color-border-subtle`、`--radius-*`、`--shadow-*`、`--font-text-*-size`；
- 组件里用 Tailwind 工具类：`text-secondary`、`bg-surface-secondary`、`border-subtle`、`heading-lg` 等，这些工具类由组件库定义；
- `web/src/styles/tokens.css` 里的 `--kw-*` 是早先写的样式在用，都指向组件库的令牌，新代码直接用组件库的变量。

| 用途 | 令牌 | 说明 |
|---|---|---|
| 主操作 | Button `color="primary"`（深色实心） | 全页最多一个 |
| 链接 | 产品色 `#2b7de9` | 链接、可点的引用、键盘焦点框；不用于按钮与大面积色块 |
| 文字 | `text-default` / `text-secondary` / `text-tertiary` | 正文、说明、弱提示 |
| 边框 | `--color-border`（输入框、表头线）、`--color-border-subtle`（行间、分割线） | 透明黑，叠在任何底色上都协调 |
| 底色 | `--color-surface`（内容区白底）、`--color-surface-secondary`（侧栏）、`--color-surface-tertiary`（用户气泡、代码框） | 不用灰色布局底 |
| 文档预览 | 底色浅灰，页面白底、发丝描边加浅投影；选中文字用系统默认的选区色 | PDF、Word、PPT 预览 |
| 功能色 | 只出现在管理后台的状态点（`ui/StatusDot`）和报错上 | 使用端的状态只写文字 |
| 字体 | 组件库的系统字体栈，后面补 PingFang SC / 微软雅黑（`web/src/styles/index.css`） | 不引网络字体 |

## 1.1 控件

1. **按钮用组件库的 Button**，默认胶囊形。`color` 只用 `primary`（主操作）、`secondary`（其余）、`danger`（删除这类不可撤销的操作）；`variant` 用 `solid`、`outline`、`soft`、`ghost`。图标按钮加 `uniform` 和 `aria-label`。
2. **二选一、三选一的切换用 SegmentedControl**。不用两个并排按钮表示切换。
3. **按钮不和输入框拼接**。搜索框用 Input 的 `startAdornment` 放搜索图标。
4. **输入框聚焦**只加深边框，不出彩色光晕（组件库默认就是这样，不要覆盖）。
5. **悬停提示**用组件库的 Tooltip，只放一句话。
6. **抽屉、弹窗顶部的操作**放在标题右侧，从左到右是切换类控件、普通按钮。抽屉（`ui/Sheet`）关闭在左上角，对话框（`ui/Dialog`）关闭在右上角。
7. **下拉菜单用 Menu**，选择框用 Select（单选、多选、可搜索都用它），开关用 Switch，勾选用 Checkbox，单选组用 RadioGroup，多个值的输入（域名、ID 列表）用 TagInput。

## 1.2 自建组件（`web/src/ui/`）

组件库没有的才自建，一律用 Radix 打底、样式只用组件库令牌，写法照组件库已有组件（`web/src/styles/ui.css`）。

| 组件 | 用途 |
|---|---|
| `Dialog`、`DialogActions` | 对话框；宽度 `sm` 520、`md` 720、`lg` 1000 三档；传 `onSubmit` 时回车提交；只显示一次的内容传 `closeOnOutside={false}` |
| `Sheet` | 右侧抽屉：文件预览、运行详情、详情查看 |
| `Tabs` | 页内标签页（文字标签加下划线） |
| `Table` | 管理页表格，前端分页，带「共 N 条」 |
| `Field`、`form.ts` | 表单项：标签、控件、说明、错误。输入框用函数子元素拿 id；选择框这类按钮式控件整块是以标签命名的 group。`useForm` 管值与校验，第一次提交前不显示错误 |
| `SearchInput`、`FilterSelect` | 工具条里的搜索框（带清除）、不带可见标签的筛选选择框 |
| `Combobox` | 边输边搜服务端的选择框（按邮箱找账号）；组件库的 Select 只能在已有选项里筛 |
| `Tree` | 可展开的树（部门） |
| `toast`（`toastStore`）、`Toaster` | 轻提示 |
| `confirm`（`confirmStore`）、`ConfirmPopover` | 对话框确认、行内气泡确认 |
| `Skeleton`、`Empty` | 加载占位、空状态（Empty 包的是组件库的 EmptyMessage） |
| `StatusDot` | 管理后台表格里的状态：圆点加文字 |
| `DescriptionList` | 详情里的「名称：值」 |
| `NumberInput`、`SecretText` | 数字输入、只显示一次的密钥 |

新的通用组件先放 `web/src/ui/`，再在这张表里登记一行。

用组件库时注意（踩过的坑）：

- 组件库的 Popover 打开时立刻把焦点移进浮层，放在抽屉或对话框里会被焦点陷阱拉回而马上关掉；要在里面放可操作的气泡，关掉它的 `autoFocus`，浮层挂好后再自己聚焦（照 `ConfirmPopover`）。
- Select 不转发 `aria-label`，按钮的名字就是当前值；用 `Field` 或 `FilterSelect` 包一层带名字的 group，测试用 `web/src/test/user.ts` 的 `pickOption`。
- 选项超过 15 个时 Select 自动出搜索框，记得传中文的 `searchPlaceholder` 与 `searchEmptyMessage`。
- 层级固定为：遮罩 1000、对话框与抽屉 1001、下拉/菜单/气泡/悬停提示 1100、轻提示 2000（`web/src/styles/ui.css` 开头）。新浮层照这几档放，不另起数字。

## 1.5 使用端与管理后台（2026-10-20 定）

同一个应用、同一套登录，两套外壳，侧栏样式相同：

- **使用端**（`/chat`、`/settings`）：员工天天用的东西，包括对话、文档预览与编辑、个人设置。侧栏不放任何管理项。
- **管理后台**（`/admin/*`）：管理员从用户菜单的「管理后台」进入。侧栏顶部是「管理后台」与「返回工作台」，导航按「组织与权限 / 能力接入 / 运营」分组，导航定义在 `web/src/layout/nav.tsx`。
- 新功能先判断归属：配置、开关、接入、授权、审计这类放管理后台；使用中的操作放使用端。例如文档编辑器（是否启用、服务地址）放管理后台，预览与编辑本身在对话页。
- 不拆成两个前端应用：单部署、同一身份体系下，两套外壳已经把管理与使用分开，省掉两套构建与登录同步。

## 2. 对话页（照 ChatGPT）

1. **居中单栏**，内容最大宽度 760px。
2. **用户消息**放浅灰圆角气泡（`--color-surface-tertiary`，圆角 20），靠右，最大宽度 70%。
3. **助手回答不套气泡**，就是正文排版，字号 15，行高 1.75。
4. **执行过程默认收起**成一行摘要，例如「已完成 4 个步骤 · 用时 38 秒」，点开才展示每一步；运行中显示当前步骤名称。写法照 `web/src/features/chat/components/ProcessSummary.tsx`。
5. **审批**用中性边框卡片：图标、标题说明要做什么、一行说明目标与工具、底部左侧「本会话内同类操作不再询问」、右侧「拒绝 / 批准」。不用黄色警告横幅。
6. **引用**用灰色小上标数字，点开看原文。
7. **文件产物**用简洁卡片：文件类型图标、文件名、类型与大小、下载按钮；可在右侧预览。
8. **回答下方**一排单色小图标：复制、有帮助、没帮助、重新生成、运行详情，带悬停提示。
9. **输入框是视觉重心**：大圆角、浅阴影、固定在底部；附件、技能选择收在框内；发送是深色圆形按钮。
10. 输入框下方一行小字提示：「回答可能有误，重要结论请点开出处核对」。
11. **使用端不上色**：状态只写文字（「已完成」「失败：原因」），不用彩色 Badge、蓝色或绿色的 Alert、带边框的折叠面板。报错只写一句原因和下一步。

## 3. 管理页（照 ChatGPT 企业管理台）

1. 页面头部：标题 20 加一句说明；下方工具条左侧搜索、右侧主操作按钮。不放第二套导航。
2. 内容直接铺在白底上，不套卡片；分组之间用标题和留白分开。
3. 表格（`ui/Table`）：
   - 操作列一律文字按钮（`variant="ghost"`、`size="sm"`），最多露 3 个，其余收进「更多」菜单；
   - 状态用 `StatusDot` 圆点加文字，同一含义全站同一颜色；
   - 名称列开 `ellipsis`，数字列右对齐（表格默认等宽数字）；
   - 列数精简，列多时给 `minWidth` 横向滚动，不出现中文被挤成一字一行；
   - 分页右对齐，带「共 N 条」。
4. 弹窗宽度只用 520、720、1000 三档，更宽改用抽屉。底部「取消 · 确定」右对齐，确定在最右，文案用动词。
5. 删除一律二次确认：行内用 `ConfirmPopover`，收进菜单的和重操作用 `confirm()`。
6. 空状态用 `Empty`，首屏加载用 `Skeleton`，后台刷新时表格变淡、不清空。

## 4. 全局规则

1. **组件只来自组件库和 `web/src/ui/`**。不引入其他组件库；页面里不手写一次性的按钮、弹窗样式。
2. **样式写法**：布局和间距用 Tailwind 工具类；需要伪类、动画、复杂选择器的写进 `web/src/styles/` 的 CSS，类名带 `kw-` 前缀。不写行内颜色。
3. **产品名称与 Logo 只经 `web/src/features/brand` 取**（`BrandMark`、`useBrand`），页面里不写死「KnowWork」：部署方可以在「管理后台 → 系统设置」换成自己的名称和 Logo。默认素材在 `web/public/brand/`：叶子 K（形状同 KnowFlow 商标图）直接当「Know」的首字母，K 和「Work」用晴空蓝 `#2b7de9`，「now」用深色 `#1d2433`；界面里的字样用网页文字，转成路径的横版只给文档用。
4. **图标只用组件库的图标**（`@openai/apps-sdk-ui/components/Icon`），尺寸跟随字号或 16 / 20；不用 emoji 作图标。
5. **提示**：`toast` 顶部居中 3 秒；不把原始错误码给用户看，错误统一经 `api/http.ts` 翻译。
6. 文案：按钮写动词（「批准」不写「确定」）；报错说清原因与下一步；中英文、中文与数字之间留空格。
7. 无障碍：文字与背景对比度达到 WCAG AA；图标按钮带 `aria-label` 或悬停提示；键盘焦点可见；表单项都有标签。
8. 亮色为准；组件库自带暗色令牌（`data-theme="dark"`），组件里不写 `isDark ? …` 分支。
9. 不主动在浏览器里验收；交付时说明是否在浏览器里看过。

## 5. 交付自查

- [ ] 只用了组件库令牌，没有颜色字面量
- [ ] 组件来自组件库或 `web/src/ui/`，没有手写的一次性控件
- [ ] 切换用分段控件，没有把按钮拼在输入框边上
- [ ] 使用端没有彩色状态、蓝色或绿色提示框
- [ ] 对话页没有给助手回答套气泡，执行过程默认收起
- [ ] 审批是中性卡片，按钮文案是动词
- [ ] 表格没有被挤成竖排，操作列是文字按钮
- [ ] 弹窗宽度在三档之内，删除有二次确认
- [ ] 空状态与加载态都有
- [ ] 图标按钮有提示文字或 aria-label
